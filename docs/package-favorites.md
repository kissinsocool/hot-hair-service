# 套餐与作品收藏

- 套餐收藏按用户、店铺和套餐保存。套餐标识与推荐卡片的 ID 一致，格式为 `店铺ID:套餐ID`。
- `GET /api/favorites/packages` 返回套餐卡片及店铺信息，`GET /api/favorites/packages/ids` 返回 `{ packageIds }`，`PUT/DELETE /api/favorites/packages/:id` 返回 `{ favorite }`。写入时套餐须在在线店铺中存在，取消收藏支持已下架套餐。
- 后端 `client-favorites` 生产新接口，小程序的首页推荐、作品详情和收藏页消费新接口。商家端无调用。原有沙龙、理发师、作品收藏接口及数据格式保持兼容，原版小程序的请求无需修改。

## 上线顺序

1. 发布后端并确认新索引和新接口可用。
2. 在新版小程序发布前执行 `node scripts/migrate-favorite-packages.js`。脚本复制旧收藏作品中可识别的关联套餐，同一用户对同一店铺套餐只保留一条套餐收藏。旧记录没有保存点击入口，作品收藏继续保留。执行完成后核对写入数。
3. 发布小程序，从作品详情分别收藏作品和套餐，验证两个标签独立显示和取消收藏。用户开始通过新版使用套餐收藏后，停止执行迁移脚本，避免重新导入已主动取消的历史套餐。仍在使用旧版的小程序会继续把作品和关联套餐按钮写入原作品收藏接口。

需要回滚时先回滚小程序，再回滚后端。保留套餐收藏集合和索引以便恢复新版本，原有收藏记录始终保存在原集合。
