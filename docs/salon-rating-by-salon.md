# 店铺评分按店铺汇总

## 行为

店铺的评分、评价数、评价列表及其筛选计数和标签统计，覆盖在该店铺下单的所有已通过评价（按订单的 `salonId`），不再取决于店铺当前的理发师名单。

- 理发师离开店铺后，其评价仍计入店铺评分，仍显示在店铺评价列表中。
- 删除并重新添加理发师不能移除店铺的差评。
- 理发师个人的评分和评价列表不变，仍按理发师汇总（`StaffRatingSummary`）。

## 存储

统计存放在店铺文档的 `ratingStats`（评价数、评分总和、差评数、中评数、带图数、标签计数、计算时间），由 `src/services/salon-ratings.js` 的 `refreshSalonRatingSummaries` 从订单重新计算，不可直接编辑。

- 该字段默认不查询，查询需在投影中加入 `SALON_RATING_STATS_SELECTION`；商家保存店铺时不会加载或覆盖它，`stripSensitiveSalonFields` 也会去掉它，不会出现在任何响应里。
- 更新 `ratingStats` 不改变店铺的 `updatedAt`。
- 评价审核通过、驳回、编辑审核通过和用户删除评价时，与理发师汇总一起重算。重算是幂等的，较早开始的计算不会覆盖较新的结果。
- 按评分排序的店铺列表直接读取 `ratingStats`，不再逐店关联理发师汇总。距离排序列表、搜索建议、收藏和店铺详情从同一次店铺查询得到评分，没有额外查询。

`bookings` 新增两个索引（`salonId` + 评价状态 + 评价时间，以及带评分的版本），供店铺评价分页和重算使用，随服务启动创建。

## 契约

响应字段不变：店铺的 `rating`、`reviewCount`，评价分页的 `items`、`total`、`counts`、`reviewTags`。消费者为小程序（店铺列表、详情、评价页、收藏）和商家端（店铺信息）。无需客户端发版。

变化仅在取值：有离职理发师评价的店铺，评分和评价数会包含这些评价。评价项里的 `staffId` 可能指向已不在店铺的理发师。

## 发布

1. 拉取代码后、重启前，先执行 `npm run ratings:rebuild`，为所有店铺写入 `ratingStats`。旧版本进程不读写该字段，不受影响。
2. 重启服务。
3. 再执行一次 `npm run ratings:rebuild`，补上两步之间通过审核的评价。

若跳过第 1 步，重启后到重建完成前，所有店铺显示为无评分。

脚本会报告"已通过但订单没有有效 `salonId`"的评价数量；这些评价不计入任何店铺，数量不为 0 时需先检查这些订单。

## 回滚

回滚代码即可恢复按当前理发师汇总；`ratingStats` 字段和新增索引可保留，旧版本不使用。
