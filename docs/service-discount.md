# 套餐折扣与价格展示

## 2026-10-30：固定售价与近似展示折扣

已核对生产者与消费者：商家端 `merchant_salon_screen.dart` 原价/折扣输入、加载归一化、`MerchantSalonRepository` GET/PATCH；后端 merchant 路由校验与计价、`serviceForStorage`/`servicePayload`、即时更新、审核草稿与发布、后台商家返回；小程序 `utils/money.js`、service-price 组件及首页/详情/预约页；预约报价与订单只消费 `priceFen`。不增加字段或必填约束。

原价和售价均明确的套餐允许 `discountTenths = round(priceFen * 100 / originalPriceFen)`，折扣为近似展示值，例如原价880、售价552、6.3折。读取、打开编辑、未修改价格信息的保存不能反算售价。已有精确折扣请求继续按原规则整元计价；旧商家端打开编辑时产生的分位重算请求，在原价/折扣未变且原套餐为近似折扣时保留已存售价。主动修改原价或折扣继续按原规则计算新售价。

兼容顺序：先发布兼容后端，再发布商家端保留已存售价的加载逻辑，最后仅回填本次16个套餐的原价与折扣并清理简介价格文字；小程序字段和渲染逻辑不变。每次数据回填前备份并检查并发变更，历史订单和其他套餐不迁移。回滚必须先按备份恢复这16个套餐的价格元数据，再回滚代码，避免旧后端清理近似折扣。

## 字段与语义

- `services[].priceFen` 始终是实际售价（分），预约、报价校验、支付和订单快照继续使用该字段，不再次打折。
- 新增可选的 `services[].originalPriceFen`：商家输入的原价（非负整数，单位分），独立保存，不从售价反算。
- `services[].discountTenths`：整数 1–100，代表 0.1–10.0 折；缺省或 null 表示不打折。有明确原价且折扣小于 100 时，后端在商家保存时将售价四舍五入到整元：`priceFen = round(originalPriceFen * discountTenths / 10000) * 100`。不打折或清除折扣时保留原价的分位。
- 兼容当前商家端按分计算的请求和今后按整元计算的请求，验证后统一保存整元售价。例如原价 99.50、9 折，商家提交 8955 分，后端保存并返回 9000 分。请求字段、类型和必填规则不变；旧编辑器单独修改实际售价的兼容逻辑保留。
- 原价 280、9.0 折保存为 originalPriceFen=28000、discountTenths=90、priceFen=25200。小程序显示 -10%、¥252、划线原价 ¥280。
- 商家端输入框明确标注“原价”。清除折扣后售价恢复为原价；重复编辑/保存从独立原价计算，不累计打折。
- 只有存在独立原价且确有降价时才显示折扣和划线原价。旧数据没有原价时只显示已保存的售价，避免反算虚构原价。
- 价格符号使用 ¥；标签为“原价”；不展示 JP 或含税。

## 兼容、部署与回滚

1. 先部署后端：原价字段可选，旧版商家只传 priceFen 仍有效。未修改售价时保留原价；旧客户端漏传或回传旧原价后修改售价，若已不满足原价/折扣关系，保留售价并清除过期原价与折扣元数据。新原价与售价不一致的请求拒绝。旧版预约请求无需原价或折扣字段。
2. 更新商家端，再更新小程序。新商家端读取没有独立原价的套餐时，将输入框中的已有价格作为待确认原价，计算折后价；保存才提交修改。因此此前误将原价280存成售价280的9折套餐，需要在新版商家端确认原价与折扣后重新保存，之后保存 originalPriceFen=28000、priceFen=25200。
3. 不批量重算线上历史数据：无法仅凭旧 priceFen 判断它原本是实际售价还是误填的原价，自动重算会改变商家的实际收费。通过商家确认保存逐条迁移。历史订单快照不改，新预约继续按服务当前售价计费，价格变动由现有确认机制提示。
4. 回滚客户端时，已保存的 priceFen 仍为正确售价。旧商家端编辑时“价格”仍按售价解释，不能把回滚客户端当作原价编辑器使用。若后端也需回滚，先停用新版原价编辑入口、备份原价数据；旧后端可能丢弃原价字段，但实际售价不变。
5. 不新增必填、不删除旧兼容；未设置折扣的旧套餐金额不变。
6. 整元规则仅需部署后端；现有商家端可以继续按分提交，小程序继续展示后端返回的售价。已有套餐在带明确原价的保存请求中更新为整元；只读查询、没有独立原价的旧请求及历史订单不重算，无需批量数据迁移。部署后商家需重新保存希望取整的旧套餐。读取不取整，确保展示与预约直接读取的数据库售价一致。
7. 回滚整元规则时应保留同时接受“分位”和“整元”两种合法售价的兼容校验，只撤销保存入口的取整步骤；不能直接回滚到只接受分位的版本，否则整元售价可能被旧逻辑清除原价元数据。已保存金额和历史订单不逆向重算；如需恢复套餐旧售价，必须依据备份由商家确认。
